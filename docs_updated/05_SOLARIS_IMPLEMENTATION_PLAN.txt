A. EXECUTION STRATEGY
Keep the already-built Households & Societies workspace working. Add commercial and installer modules to shared APIs with organisation-scoped RBAC. Build exact calculation engine before the visually exciting mall. Seed deterministic demo data and verify with tests. Integrate Helios after tool APIs are stable. Work in vertical slices with a runnable build after every phase.

B. SPRINT 0 — REPO AUDIT & BACKUP (FIRST)
Tasks: inspect repository tree, frontend/backend stack, existing routes, auth model, tables, deployed APIs and household functionality; enumerate implemented vs mock vs missing; create branch and baseline tests; identify migration and integration risks. DO NOT start by replacing residential auth or hardcoding a new platform from scratch.
Artifacts: repo inventory.md, migration approach, preexisting feature checklist, failing/passing tests.
Exit criteria: existing household login, billing and dashboard paths verified on development environment.

Tests: tenant A / tenant B isolation, cross-project file forbidden, installer cannot read household budgets, switching URL alone grants nothing, platform admin not universal private bill reader.
Exit criteria: permissions tested at API layer; residential data preserved.

D. SPRINT 2 — COMMERCIAL DATA + BILL INTELLIGENCE [P0]
Tasks: synthetic mall, shops, main meter + sub-meter tree; 12 synthetic monthly bills; manual bill entry/import; tariff/period config; candidate 100/200/300 kWp scenarios; robust before/after engine; breakdown charts; stored assumptions and results. E. SPRINT 3 — SOLARMATCH + INSTALLER WORKFLOW [P0]
Tasks: single SolarMatch workflow for household, society and mall inputs; residential consumption+roof+location+budget+policy readiness; commercial load+roof+project size+tariff/region; capacity precheck; installer hard filters, transparent weighted rank, 3 demo fictional companies; quote request, assigned company dashboard, quote form, quote comparison.
Tests: incorrect service region excluded; capacity mismatch excluded; missing credential shown unknown; ranked reasons reproducible; unassigned installer cannot view quote.
Exit criteria: can request and receive one quote end-to-end using separate buyer/installer accounts.

F. SPRINT 4 — VISUAL MALL + TENANT LEDGER [P0]
Tasks: responsive React Three Fiber generic 3D mall or performant existing 3D solution, floor selector, click-to-inspect shop, green/amber/blue/grey/red labelled states, tenant shop panel, optional 2D floor grid; seeded internal tenant benefit policy and per-shop statements. Show external DISCOM vs internal benefit type prominently. Use no 'all shops VNM-approved' shortcut.
Tests: shop geometry key matches backend; tenant can view only own statement; sum of allowed benefit allocations <= available eligible pool; all mock credentials/data labelled demo; 2D accessibility fallback.
Exit criteria: judge clicks a shop and understands kWh, agreement, benefit type and savings in under 10 seconds.

G. SPRINT 5 — HELIOS (GEMINI) [P0]
Tasks: floating 'Ask Helios ☀️' panel in every workspace, compact quick questions, Gemini backend integration, curated FAQ/docs, read-only allowlisted tool calls. Tools: get_my_statement, explain_benefit, get_property_summary, compare_system_sizes, find_installers, compare_quotes, get_project_status. Backend checks permission independently per tool call. Provide sources/assumptions; fail gracefully offline.
Tests: tenant requests competitor shop bill -> denied; unauthorised installer requests property financials -> denied; missing bill => admit unknown; false request to 'change allocation' => no write tool; model output includes correct figures from deterministic engine.
Exit criteria: Helios solves 5 standard role-specific questions and 2 negative security tests; fun but accurate tone.

H. SPRINT 6 — RESIDENTIAL CONTINUITY + SMARTEXIT [P1]
Tasks: inspect residential status; preserve original VNM reconciliation, affordability-aware optimisation and ownership records; link household SolarMatch; ensure Helios handles household FAQs; where time remains, improve SmartExit ownership-transfer/funding-gap differentiation with CP-SAT and versioned approval states.
Tests: flat leaves fully paid system -> no assumed funding gap; share transfers remain proposed until consent and external approval; no automatic DISCOM changes.
Exit criteria: residential MVP runs side by side with commercial/installer modules.

M. END-TO-END DEMO SCRIPT (3–5 MIN)
1 Open Solaris: three clear workspace cards. Mall operator login.
2 Commercial dashboard: interactive mall, colour labels and savings KPI.
3 Upload/review bill; click 'Compare solar options'; show before/after for 100/200/300 kWp.
4 SolarMatch recommends 3 suitable demo installers with reasons; send RFQ.
5 Switch to installer login: view assigned RFQ, submit a quote, update milestone.
6 Switch back: inspect a green shop, view 'Internal benefit adjustment' statement; explain distinction from official VNM.

Close: Solaris makes solar decisions data-driven, procurement easier and benefits transparent.
